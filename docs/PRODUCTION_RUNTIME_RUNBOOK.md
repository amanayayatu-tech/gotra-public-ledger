# GOTRA Public Ledger Production Runtime Runbook

This runbook records the public web-edge runtime boundary for
`gotra-public-ledger`. It is operational evidence only. It is not formal
acceptance, science/public proof, performance proof, investment advice, a
trading signal, or proof of stable long-run automation.

## Canonical Entry Point

- Canonical production URL: `https://gotra.me/`
- Canonical production report artifacts:
  `/var/www/gotra-public-ledger/reports/*.json` and
  `/var/www/gotra-public-ledger/reports/*.md`
- GitHub Pages is manual fallback/debug static hosting only. Pages artifacts
  must not be treated as the source of production status.
- `.github/workflows/pages.yml` is intentionally `workflow_dispatch` only so a
  Pages deploy failure does not mark the canonical `gotra.me` production path as
  failed.

## Port Boundary

Expected public TCP exposure:

- `22`: SSH, kept according to current server operations policy.
- `80`: HTTP redirect to HTTPS.
- `443`: HTTPS.

Expected non-public ports:

- `631`: CUPS/IPP must be disabled or blocked from public access.
- `3000`: backend API must bind `127.0.0.1:3000` only.
- `7777`: unused by this public deployment and must not be publicly reachable.

Host-side smoke:

```bash
ss -lntup
nft list ruleset
nginx -t
curl -I https://gotra.me/
curl -I http://gotra.me/
```

External-side smoke must be run from a non-server network:

```bash
nc -vz gotra.me 631
nc -vz gotra.me 3000
nc -vz gotra.me 7777
nc -vz gotra.me 80
nc -vz gotra.me 443
```

Pass criteria: `631/3000/7777` are not connectable, and `80/443` are reachable.

## Deploy Boundary

Build and deploy the frontend without deleting live report artifacts:

```bash
cd /opt/gotra-public-ledger
GOTRA_REPORTS_DIR=/var/www/gotra-public-ledger/reports npm run build
rsync -avc --delete --exclude="/reports/*.json" --exclude="/reports/*.md" dist/ /var/www/gotra-public-ledger/
find /var/www/gotra-public-ledger -type d -exec chmod 755 {} +
find /var/www/gotra-public-ledger -type f -exec chmod 644 {} +
nginx -t
```

The `rsync` excludes are required. The production report JSON and Markdown files
are generated by backend runtime services and must not be replaced by an empty
frontend build.

## Npm Audit Strategy

Current moderate audit findings are from dev-only `lighthouse`, which pulls
`@sentry/node` and `@opentelemetry/*` into local audit tooling. The production
browser bundle does not import `lighthouse`, `@sentry/node`, or OpenTelemetry
server instrumentation.

Policy:

- Do not run `npm audit fix --force` for this issue; npm suggests a semver-major
  downgrade path for `lighthouse`.
- Keep the finding documented as dev-only unless a runtime dependency path
  appears in the production bundle.
- Recheck with `npm audit --json` during dependency maintenance.
- If upgrading `lighthouse` or replacing the audit toolchain, run
  `npm run typecheck`, `npm run lint`, `npm run test`, `npm run build`,
  `npm run geo:smoke`, `npm run compliance:scan`, and
  `npm run secrets:scan`.
